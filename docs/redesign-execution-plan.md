# План внедрения «Рабочей станции»

Дата: 2026-10-02. Визуальный источник: **вариант 02** в [design-directions.html](design-directions.html). Этот документ уточняет [план направления](design-workstation-plan.md); фактическое выполнение отмечается в [журнале](redesign-progress.md).

## Результат и границы

Учитель быстро находит группу, назначает работу и проверяет результаты. Студент видит доступные задания, расписание и завершённые попытки. Навигация, плотность и визуальная иерархия едины. Сохраняются Vue 3, Bootstrap, Pinia, Django API, роли, права доступа, прямые ссылки, RU/EN и работа с черновиками. Демонстрационные числа и действия из HTML не становятся данными приложения.

Первая поставка: общая оболочка, токены и разделение главных страниц по рабочим разделам. Следующие этапы — глубокая переработка содержимого группы, материалов и попытки. Завершение первой поставки не означает завершение всего редизайна.

## Скиллы и способ применения

| Инструкции | Где применяются | Проверяемый результат |

| [Vue Best Practices](https://github.com/vuejs-ai/skills/tree/main/skills/vue-best-practices) | Composition API, границы компонентов, props/events, вычисляемые состояния маршрута | Нет второго источника состояния вкладок; общая навигация выделена; API и бизнес-правила не дублируются |
| [Web Design Guidelines](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines) и [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines) | Проверка подписей, фокуса, форм, loading/error/empty, переполнения, reduced motion | Проверены русские и английские строки, узкие экраны, пустые и ошибочные ответы |
| UI UX Pro Max | Только точечный справочник: dense dashboard, ошибки форм | Рекомендации сверяются с Vue и выбранным макетом; генератор общей эстетики не используется |

Прочитанные версии закреплены в `.runlogs/design-skill-research/selected/manifest.json`. Используются тексты инструкций, а не автоматически установленные движки или hooks. Полное сравнение и ограничения: [исследование](design-skills-research.md).

## Визуальный контракт

- Тёмная навигация `#192738`, активный пункт `#30445e`; рабочий фон `#eef1f5`, белые поверхности, текст `#1f2d3d`, вторичный текст `#5c6878`, синий акцент `#315dcc`.
- Один системный шрифт с кириллицей. Основной текст 14–16 px, заголовок страницы 26–30 px. Числа табличные. Небольшие радиусы 6–8 px, спокойные границы, без стекла и декоративных градиентов.
- На широком экране постоянная боковая панель, верхняя строка пользователя и языка. На телефоне навигация остаётся видимой компактной полосой; действия не зависят от hover.
- Вкладки подчёркнуты; primary обозначает основное действие. Статусы различаются текстом и цветом. Фокус заметен. Нельзя прятать функциональные данные только ради сходства с демо.
- Данные таблиц не мельче 14 px; на телефоне строки становятся блоками или получают локальную прокрутку с доступным названием. Вся страница не прокручивается по горизонтали.

## Границы компонентов

`App.vue` отвечает за каркас, язык и выход. `AppSidebar.vue` только отображает переданные пункты и активность. `useWorkspaceNavigation` вычисляет пункты по роли и route, не делает запросов. Главные страницы владеют загрузкой данных и формами; `computed` выбирает раздел из URL. Редакторы и попытки остаются владельцами собственных бизнес-состояний. Новые абстракции вводятся только при реальном повторении.

## Порядок и возврат

Сначала токены/каркас, затем главные страницы, затем отдельные рабочие сценарии. Каждая поставка проверяется до следующей. Изменений моделей/миграций/контракта API для визуального этапа не требуется. Возврат первой поставки возможен отдельным откатом файлов frontend; рабочая база данных не изменяется. Тестовые записи создаются только во временной БД либо в явных браузерных fixtures.
