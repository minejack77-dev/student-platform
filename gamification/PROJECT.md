## Рейтинг уже есть

В [GroupViewSet](../learning/views.py), `_build_group_ranking_rows` (строка 636), считаются завершённые и зачтённые работы, правильные ответы и пропуски готовых прошедших назначений. Основная сортировка — доля зачётов среди завершённых и учтённых пропущенных работ, затем число правильных ответов; далее используются имя и ID.

Метод `ranking` (строка 1325) отдаёт студенту только его место, динамику и размер группы. Преподаватель получает строки рейтинга в рамках действующего доступа. Главная студента сейчас запрашивает рейтинг группы из первого элемента списка назначений (`loadRanking`, строка 124); полноценного выбора группы здесь нет.

Следствие: общий рейтинг XP не следует вводить как будто рейтинга пока нет. Он создаст вторую систему сравнения и потребует объяснять расхождения. Предлагается сохранить учебный рейтинг отдельно, а игровой прогресс сделать личным. Публичную таблицу фамилий из существующего API автоматически не открывать.

## Ограничения, влияющие на выбор механик

1. **Одно назначение — одна попытка.** Ограничение БД `uq_attempt_student_schedule_entry` и создание в `AttemptSerializer.create` предотвращают повтор для того же назначения. Новый повтор потребует нового назначения либо отдельного тренировочного режима.
2. **Работать можно в дату назначения.** `require_schedule_access` сверяет её с `timezone.localdate()`; проверяются также активность материалов и членство. Ежедневная серия и квест «пройди ещё три теста» могут быть недостижимыми из-за расписания.
3. **Одинаковые задания могут назначаться повторно.** Уникальность попытки на назначение не исключает повтор того же `Task` в другие дни или группы. Это отдельный случай для защиты XP от накрутки.
4. **Сложность не размечена.** Разный объём тестов и случайный набор вопросов не делают их сопоставимыми по сложности. Нельзя превращать сумму правильных ответов в достоверную оценку мастерства.
5. **Разбор после сдачи показывает правильные ответы.** Повтор уже знакомого теста может проверять запоминание ключа. Для подтверждения освоения нужны новые эквивалентные задания.
6. **История членства не хранится в GroupStudent.** Там нет `joined_at`/`left_at`. Текущий состав группы не позволяет надёжно восстановить, какие старые задания действительно были доступны конкретному студенту. Для недельных целей и знаменателя метрик понадобится фиксация доступных назначений.
7. **Учебная программа не зафиксирована как версия.** Иерархия материалов существует, но нет неизменяемого списка обязательных заданий для конкретной программы. «Раздел пройден на 100%» требует такой спецификации: иначе добавление задания изменит старый результат.
8. **Старые снимки имеют оговорку.** `capture_question(..., legacy=True)` помечает их `legacy_current_content_not_verified`. Без проверки исторических данных нельзя автоматически выдавать по ним значимые подтверждения компетенций.
9. **Права уже разделены.** Владелец материалов, руководитель группы и назначенный преподаватель — не обязательно один человек. Новые достижения и отчёты должны использовать сопоставимую область доступа, включая отзыв назначения.

## Точки интеграции и технические особенности

| Файл / символ | Наблюдение | Предлагаемое применение |
|---|---|---|
| [attempts.py](../learning/services/attempts.py), `submit_attempt` | Транзакция, блокировка попытки, повторная сдача completed возвращает результат | После проверки создать событие награды с защитой от дубликатов |
| [models.py](../learning/models.py), `complete_attempt` | `post_save` проверяет ответы и обновляет `is_success` через QuerySet | Использовать результат после `refresh_from_db`; не начислять на каждый `post_save` |
| [serializers.py](../learning/serializers.py), `AttemptSerializer.update` | Старый путь обновления тоже делегирует `submit_attempt` | Подключение к общему сервису охватит оба API-пути |
| [snapshots.py](../learning/services/snapshots.py) | Снимок вопросов отделён от изменяемого банка | Сохранять основание награды и версию её правила |
| [permissions.py](../learning/permissions.py) | Доступ по роли и группе/назначению | Не выдавать награды и чужую историю через произвольный ID |
| [StudentHomePage.vue](../student-platform-frontend/src/views/StudentHomePage.vue) | Важный блок «Сегодня» и календарь | Компактная карточка прогресса после текущих заданий |
| [AttemptDetail.vue](../student-platform-frontend/src/views/AttemptDetail.vue) | Разбор, результат, число верных ответов | Объяснение начисления рядом с результатом |
| [tasks.py](../learning/tasks.py) | Есть фоновые напоминания | Очередь обработки достижений и сверка пропущенных событий |

Перед расширением push нужно отдельно поправить и проверить семантику существующих задач: `send_test_reminders` выбирает сегодняшние задания, но текст говорит «tomorrow»; `send_push_notifications` считает назначения без исключения завершённых попыток. Это наблюдения по коду, не подтверждённые случаи ошибочной доставки на сервере. MVP может обходиться без новых push.

Не найдены готовые модели XP, уровней, выдачи достижений, сезонов, навыков, тренировочного повторения или журнала продуктовых событий. Эти возможности в отчёте далее помечены как предлагаемые.
