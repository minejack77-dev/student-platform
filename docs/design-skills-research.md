# Исследование скиллов для «Рабочей станции»

Дата: 2 октября 2026 года. Проект: Student Platform, выбранный вариант 02 из [design-directions.html](design-directions.html).

## Рекомендация

Основной кандидат — **Impeccable в режиме Operate**: его инструкции непосредственно охватывают кабинеты, таблицы, формы и рабочие приложения. Для реализации добавить **Vue Best Practices**, для независимой проверки — **Vercel Web Design Guidelines**. **UI UX Pro Max** использовать выборочно для поиска конкретных UX-правил. Его автоматическую генерацию дизайн-системы не принимать за проектную спецификацию: локальная проверка показала существенное расхождение с нашей задачей.

Более простой вариант без движка Impeccable — **Anthropic Frontend Design + Vue Best Practices + Web Design Guidelines**, с нашим макетом и планом в качестве обязательного задания. Одновременно активировать два набора художественного руководства не нужно.

Это вывод о пригодности инструкций к проекту, а не доказанное превосходство качества сгенерированных экранов. Полноценный сравнительный эксперимент по реализации UI не проводился.

## Метод и границы исследования

Сравнены восемь публичных кандидатов/семейств: Impeccable, UI UX Pro Max, Anthropic Frontend Design, Vue Skills, Vercel Web Design Guidelines, Design System Patterns, Taste Skill и Anthropic Webapp Testing. Дополнительно учтены пять непосредственно прочитанных в предыдущем проходе файлов skills.md: Site Analyze, Brand Style Guide, Dashboard Builder, Microcopy Generator и Color Palette Harmonizer.

Проверялись сами SKILL.md, связанные инструкции и исходники, а не только карточки каталога. Для UI UX Pro Max выполнено шесть локальных запросов к зафиксированной версии. Спорные технические рекомендации сверены с документацией Vue и Playwright. Число звёзд, загрузок и рекламные обещания не использовались как доказательство качества.

Подтверждённый контекст проекта: Vue 3.5, Bootstrap 5.3, Pinia 3, Vue Router 5, JavaScript с `<script setup>`, RU/EN, Django API и PWA. Дизайн уже выбран: графитовая навигация, светлый фон, компактные таблицы и радиус около 7 px. Смена фреймворка, новая палитра или превращение кабинета в лендинг не являются успехом.

Скиллы не установлены в каталоги агента. Для исследовательского запуска скачана изолированная часть UI UX Pro Max в `.runlogs/design-skill-research/`; установщик, внешние модельные API и платные сервисы не запускались. Приложение и база не менялись.

## skills.md и skills.sh — разные источники

У skills.md есть удалённые операции, каталог и отдельная система запуска. Его пять проверенных файлов оказались недостаточной основой для комплексного редизайна: четыре почти не содержат методики, Site Analyze описывает извлечение визуальных характеристик. Это ограниченный вывод по прочитанным файлам, не утверждение о бесполезности всего сервиса. [Документация skills.md](https://skills.md/docs), [предыдущая проверка](design-workstation-plan.md#проверка-скиллов-skillsmd).

skills.sh содержит карточки скиллов из репозиториев, в том числе [Frontend Design от Anthropic](https://skills.sh/anthropics/skills/frontend-design). Название `skills` используется разными CLI: `@hasna/skills` и инструмент Vercel — разные пакеты. Их команды нельзя смешивать. В этом исследовании первичным источником служил репозиторий автора, а карточки — способом поиска. [CLI Vercel](https://github.com/vercel-labs/skills).

## 1. Impeccable: наиболее подходящий основной набор

Ключевое отличие — [Operate](https://github.com/pbakaus/impeccable/blob/main/skill/reference/operate.md). Для рабочего интерфейса приоритет отдан привычным элементам управления, сканируемости, спокойной типографике и последовательным состояниям. Это соответствует варианту 02 гораздо лучше, чем универсальная установка на эффектность. Основной файл также явно ставит выбранный пользователем бриф выше собственных вкусовых предпочтений. [Основные инструкции](https://github.com/pbakaus/impeccable/blob/main/skill/SKILL.src.md).

Полезные операции для нашей работы:

| Операция | Конкретная задача |
|---|---|
| `extract` | Выделить токены и общие элементы из варианта 02 и переносимых Vue-экранов |
| `critique` | Проверить, заметны ли текущее назначение, результаты и основное действие |
| `adapt` | Перевести плотные строки в удобное мобильное представление |
| `harden` | Проверить длинные имена, RU/EN, пустые списки, ошибки API и двойные клики |
| `clarify` | Согласовать «Начать», «Продолжить», «Результат» и сообщения о сохранении |
| `audit` | Найти подтверждаемые проблемы доступности, адаптивности и реализации |
| `polish` | Закончить выравнивание и оформление после работающих сценариев |

Назначения команд проверены в [основном файле](https://github.com/pbakaus/impeccable/blob/main/skill/SKILL.src.md); подробнее прочитаны [harden](https://github.com/pbakaus/impeccable/blob/main/skill/reference/harden.md), [audit](https://github.com/pbakaus/impeccable/blob/main/skill/reference/audit.md) и [clarify](https://github.com/pbakaus/impeccable/blob/main/skill/reference/clarify.md).

Уточнения для применения: новая тёмная тема, поддержка дополнительных языков и работа без JavaScript не следуют автоматически из общей инструкции harden. В нашей SPA проверяем реальные RU/EN, состояния сети и существующий PWA-контракт. «Работает офлайн» нельзя обещать лишь потому, что есть service worker.

`shape` предназначен для уточнения замысла и возвращает бриф, завершаясь подтверждением. У нас уже есть выбранное направление и план, поэтому обязательное повторное интервью не нужно; загружать эту команду имеет смысл только для действительно нерешённого нового сценария. Это описание поведения исследуемого файла, а не действующий запрос согласования. [Shape](https://github.com/pbakaus/impeccable/blob/main/skill/reference/shape.md).

Цена интеграции выше, чем у одиночного Markdown: актуальная поставка содержит launcher и движок; первый запуск может скачать бинарник. Полная установка также может добавить hooks. Для Windows предусмотрен `.cmd`. Перед подключением следует выбрать минимальную проектную поставку и проверить её состав; библиотека инструкций и работа движка — разные уровни проверки. [README](https://github.com/pbakaus/impeccable#installation).

## 2. UI UX Pro Max: реальная проверка вместо обещаний

Протокол: скачаны выбранные скрипты и CSV на commit `09170eec67eefd46a7ae85de61b40c194020f997`; перед запуском просмотрены импорты и операции ввода/вывода. Использован Python без установки зависимостей. Каждый запрос запускает поисковый скрипт локально. `--persist` и `--force` не использовались. В [JSON с результатами](design-skills-probe.json) есть аргументы, stdout в разобранном виде, exit code, ссылки на точные файлы и SHA-256.

| Запрос | Наблюдение | Решение |
|---|---|---|
| `education learning management dashboard --design-system --density 8` | Категория LMS распознана. При этом предложены лендинг с hero/features/CTA, бирюзовая палитра, Baloo 2 / Comic Neue, дополнительные продуктовые функции | Не переносить эту систему в проект |
| `internal operations dashboard --design-system --density 8` — одно уточнение | Шрифты стали Fira Code / Fira Sans, но композиция осталась Hero + Features + CTA; категория General | Генератор всё ещё не заменяет выбранный макет |
| `data dense dashboard --domain style` | Один релевантный результат: компактные таблицы, метрики, сетка | Использовать принципы плотности, не автоматически размеры и перечень функций |
| `error summary validation --domain ux` | Три результата о сводке ошибок, объявлении ошибок и привязке к полю | Полезно для редактора вопросов и импорта |
| `keyboard focus modal --domain ux` | Три результата о видимом/неперекрытом фокусе | Частичное покрытие: запрос не дал полного протокола диалога |
| `computed filtered list --stack vue` | Три результата: computed, v-memo, разделение v-if/v-for | Полезный поиск, но кодовые фрагменты требуют технической проверки |

Все шесть процессов завершились с кодом 0. Это подтверждает работоспособность выбранных поисковых путей, а не корректность всех рекомендаций или готовность конечного дизайна. Проба не передавала генератору полный бриф или HTML и не оценивает последующую способность агента отфильтровать рекомендации. Она показывает, почему автоматический результат по тематическим ключевым словам нельзя принимать без проверки.

Для сохранённых фрагментов выдачи приложена [лицензия исходного набора UI UX Pro Max](design-skills-probe.LICENSE.txt).

Обнаружена конкретная техническая ловушка: в результате Vue пример `v-memo="[item.id]"` помечен как хороший. Для строки с изменяемым результатом при стабильном ID такое условие может пропустить необходимое обновление. Это вывод по семантике директивы, не воспроизведённый баг приложения. Официальная документация требует корректного массива зависимостей и относит v-memo к редким микрооптимизациям. [Vue v-memo](https://vuejs.org/api/built-in-directives.html#v-memo).

Вывод: применять явные `--domain ux`, `--domain style` и `--stack vue`, формулировать одну задачу за раз, сверять выдачу. Не добавлять из результатов форумы, экспорт, графики и новый шрифтовой набор без задачи на эти функции. Поиск — способ получить кандидатов на решение. [Инструкции проверяемого скилла](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/09170eec67eefd46a7ae85de61b40c194020f997/.claude/skills/ui-ux-pro-max/SKILL.md).

## 3. Anthropic Frontend Design: лёгкая альтернатива

Прочитанная версия предлагает сначала определить визуальную систему по брифу, затем проверить план и реализовать его, выполняя самокритику. Она явно разрешает заданному пользователем направлению преобладать над собственным списком нежелательных шаблонов. Для нас это означает сохранить тёмный sidebar, светлые таблицы и спокойные шрифты, даже если подобная структура часто встречается в SaaS. [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md).

Пригоден для небольшого первого переноса и не требует отдельного поискового движка в самой инструкции. Однако файл короче и меньше помогает с подробными состояниями рабочего кабинета. Выбирать его как альтернативу основному Impeccable, не как второй одновременно действующий художественный стандарт.

## 4. Vue Skills: полезны для реализации, не для выбора стиля

`vue-best-practices` содержит последовательный процесс: границы компонентов, props/emits, реактивность и composables. Это полезно для разделения больших StudentHomePage и GroupOverview на оболочку, фильтры, строки и состояния. [SKILL.md](https://github.com/vuejs-ai/skills/blob/main/skills/vue-best-practices/SKILL.md).

Два ограничения: по умолчанию предлагается TypeScript, а наш код на JavaScript; редизайн не повод проводить языковую миграцию. Кроме того, количество компонентов должно следовать реальным обязанностям, а не механически расти ради соблюдения шаблона. Сам проект Vue Skills обозначен автором как эксперимент сообщества, его не следует представлять как официальную библиотеку Vue. [README](https://github.com/vuejs-ai/skills).

`vue-router-best-practices` потенциально полезен для вкладок/query и повторного использования компонентов маршрута, но его заявленная область — Router 4, тогда как в package.json проекта Router 5. Применять после проверки конкретных правил по используемой версии, не подключать весь набор автоматически. [Файл router-скилла](https://github.com/vuejs-ai/skills/blob/main/skills/vue-router-best-practices/SKILL.md).

## 5. Vercel Web Design Guidelines: независимая проверка

Сам SKILL.md короткий, но это обоснованно: он ссылается на содержательный отдельный [набор правил](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md) и требует выводить проблемы с указанием файла и строки. Есть проверки фокуса, подписей полей, переполнения, сохранения состояния в URL и сообщений об ошибках. [SKILL.md](https://github.com/vercel-labs/agent-skills/blob/main/skills/web-design-guidelines/SKILL.md).

Применять после готового экрана. JSX, React-гидрацию и предложения библиотек переносить только по смыслу. Например, URL вкладки у нас обслуживает Vue Router; английский Title Case не является правилом русских заголовков. Совет о виртуализации не повод вводить её для любой таблицы из 50 строк: решение принимать по объёму и измерениям. Это набор инженерных эвристик, не сертификат доступности.

## 6. Вспомогательные и отклонённые варианты

**Design System Patterns** полезен иерархией токенов: значение → смысл → компонент. Для проекта достаточно CSS custom properties и нескольких переиспользуемых Vue-элементов. React theme providers, многобрендовая система, Style Dictionary и синхронизация Figma не нужны без отдельной потребности. [SKILL.md](https://github.com/wshobson/agents/blob/main/plugins/ui-design/skills/design-system-patterns/SKILL.md).

**Taste Skill:** актуальный основной файл явно ограничивает область лендингами, портфолио и похожими редизайнами. Его исключение таблиц и многошагового product UI — достаточная причина не выбирать его для основной задачи. [Основной файл](https://github.com/Leonxlnx/taste-skill/blob/main/skills/taste-skill/SKILL.md).

В том же репозитории **redesign-existing-projects** обещает сохранять стек, но одновременно рекомендует текстуры, асимметрию и альтернативы левому sidebar. Для выбранного нами плоского рабочего дизайна это создаёт ненужные конфликты. Вручную можно взять аудит состояний, но подключать весь файл как главный стандарт не рекомендую. [Redesign](https://github.com/Leonxlnx/taste-skill/blob/main/skills/redesign-skill/SKILL.md).

**Anthropic Webapp Testing** соответствует уже используемому в проекте Python Playwright. Полезны управление сервером, инспекция DOM и скриншоты. Однако настойчивая рекомендация использовать networkidle расходится с актуальной документацией Playwright, где для тестов рекомендуются проверки ожидаемого состояния интерфейса. Использовать подход к тестированию с этой поправкой. [Скилл](https://github.com/anthropics/skills/blob/main/skills/webapp-testing/SKILL.md), [Playwright](https://playwright.dev/python/docs/api/class-page#page-wait-for-load-state).

Имеющиеся Figma-скиллы становятся уместны, если понадобится отдельный редактируемый макет/библиотека в Figma. Для переноса локального HTML в существующий Vue-код это дополнительный маршрут, не обязательный этап. Генерация картинок также не решает главную задачу плотных таблиц и форм.

## Предлагаемый порядок использования

| Этап плана обновления | Скилл | Конкретный результат |
|---|---|---|
| Зафиксировать ограничения | Наш макет и проектный бриф; Impeccable Operate как методика | Единый список решений: палитра 02, роли, маршруты, RU/EN, состояния |
| Выделить общую основу | Impeccable extract; Design System Patterns только при необходимости | Семантические токены и небольшой набор общих компонентов |
| Перенести два контрольных экрана | Impeccable + Vue Best Practices | Рабочие назначения ученика и обзор группы с существующим API |
| Решить отдельную UX-проблему | UI UX Pro Max, целевой запрос | Проверенное правило, применённое к конкретной форме/таблице |
| Проверить ширины и данные | Impeccable adapt/harden/clarify | Устойчивые строки, RU/EN, ошибки, пустые состояния, понятные действия |
| Независимый аудит | Vercel Web Design Guidelines | Замечания с файлами/строками и приоритетами |

Не нужно вызывать все операции на каждой кнопке. Основной дизайн-скилл работает на этапе проектирования/переноса, технический — при Vue-изменениях, аудит — после готового фрагмента.

## Бриф, который должен сопровождать любой выбранный набор

> Перенеси Student Platform на вариант 02 «Рабочая станция» из docs/design-directions.html. Макет и docs/design-workstation-plan.md задают визуальное направление. Это учебное рабочее приложение: преподаватель управляет группами и назначениями, ученик проходит тесты и смотрит результаты. Сохрани Vue 3, JavaScript, Bootstrap, действующие API, права доступа, RU/EN и правила попыток. Используй тёмный sidebar, светлые поверхности, компактные читаемые строки и существующую палитру варианта 02. Не добавляй маркетинговый hero, новые функции и библиотеки из общих рекомендаций скилла. Сначала выполни один законченный фрагмент для обеих ролей; проверь его на desktop/mobile, с длинными данными, загрузкой, пустотой и ошибкой.

Это проектные ограничения, сформулированные по коду и выбору пользователя; они не являются выдержкой из внешнего скилла.

## Что считать подтверждением пользы

После подключения выбрать один небольшой рабочий фрагмент: назначения ученика и таблицу результатов группы. Оценивать сохранение функций, соответствие варианту 02, читаемость, мобильную версию, RU/EN и отсутствие ложных данных. Фиксировать конкретные исправления и затраченную работу. Если скилл самовольно меняет стек, палитру или структуру продукта, такой результат отклонять независимо от эффектности.

На сегодня подтверждены содержательность инструкций и шесть поисковых запусков UI UX Pro Max. Не подтверждены: качество полного редизайна с каждым кандидатом, работа Impeccable launcher/hooks в этой среде и доступность платных операций skills.md. Перед установкой следует закрепить выбранную версию и читать полный состав пакета, включая references; копии одного SKILL.md не всегда достаточно.
