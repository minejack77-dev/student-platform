    Критерии решения

    Больше выполненных работ.
    Сохранённое качество.

    • Считать только действительно доступные назначения.
    • Проверять знания на новых эквивалентных вопросах.
    • Спрашивать студентов о понятности и давлении.
    • Учитывать исходные различия групп и неопределённость.
    Такой график сам по себе не доказывает причинный эффект. Для решения нужен пилот, сопоставимые условия и достаточная выборка.

    04 / ПРОДОЛЖЕНИЕ

    Следующая цель

    Другое доступное задание. Если работ нет — спокойная пауза.

    Простая экономика опыта

    Первое полное завершение задания+10 XP
    Первый зачёт задания+20 XP
    Повторное начисление за то же основание0 XP
    Пропуски и неудачибез штрафов

    Лимит — 30 XP за одно задание в программе. Бейджи не дают дополнительных XP. Учебный рейтинг остаётся отдельным.

    Пять ступеней личного пути

    Пример для программы минимум с 20 разными заданиями. Для короткого курса пороги нужно настроить до запуска.

    1Старт0 XP
    2Первые шаги60 XP
    3Практика150 XP
    4Опыт300 XP
    5Большой путь600 XP

    Это объём учтённой работы, а не шкала квалификации. Сравнивать абсолютный XP разных групп некорректно.

    Техническая схема: как избежать повторных наград
    Сдача и проверка→Событие в БД→Фоновая обработка→Журнал XP и бейджей→Обновление кабинета

    Событие сохраняется вместе с результатом попытки. Обработчик создаёт только отсутствующие награды; ограничения уникальности в БД защищают от повторов. При сбое очереди событие подхватит сверка, а студент увидит «Прогресс обновляется». В HTML всё моделируется локально; интеграции с API здесь нет.

    В проекте уже есть Django/DRF, Vue, Celery, проверка попыток и снимки вопросов. Понадобятся программа, журнал начислений, выдача бейджей и история доступных назначений. Полная спецификация — в IMPLEMENTATION.md.
